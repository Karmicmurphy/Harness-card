# Thousand-Year Hangover — continuity recovery adapter

**Role:** A narrow bridge from Harness skill routing to an **independent creative project**. This is NOT story canon, an archive of private personal history, a FRIDAY runtime feature, or a license to modify creative assets.

**Source of truth:** The owner's private ChatGPT Library folder `The Thousand Year Hangover! Never Ending Saga!`, using its latest owner-approved `THY_Continuity_Recovery_SKILL.md`, `THY_Complete_Thread_Handoff_2026-10-26.md`, and `THY_Asset_Manifest_2026-10-26.json`. Load those three through *owner-authorized* Files/Library tools whenever the user requests recovery or continuation. The Library holds the full creative context; this public file is **only a non-sensitive locator and procedure**.

## Triggers

Use when the user explicitly names Thousand-Year Hangover / THY and asks to find the original film, continue an episode, recover Ollie's voice, locate the saved handoff, resume the saga, or stop drift. Do **not** route an unrelated creative conversation or an ordinary FRIDAY work order here.

## Strict sequence

1. **Separate the project.** THY is a distinct creative universe. Never classify its media/story as Foundation V0, CTOS, a FRIDAY execution job, an engineering governance input, or the current `state/CURRENT_PROJECT.json` active work order. Use existing Harness methodology without promoting THY into machine authority.
2. **Recover the latest saved handoff before proposing changes.** With user-authorized ChatGPT Files/Library access, enumerate the named Library folder, read its THY-specific skill, handoff, and manifest, and refresh provider evidence only as needed. If this runtime lacks Files access, say `BLOCKED: private Library access unavailable`. No guessed access, raw bytes, file refs, or links.
3. **Locate, do not rebuild.** Search for `THY_Episode_001_The_Noise_Inside_FIRST_CUT_v2.mp4` and other exact manifest identities. The existing in-house first cut, original user Google Flow/CapCut source, storyboard concepts, and later approved Ollie voice are separate artifacts. Do not infer a newer voice was mixed into an older render.
4. **Proof levels are separate.** Provider file metadata proves existence only. Raw-byte extraction, actual audiovisual playback, ending frame, Android opening, and user approval each require their own observation. Report unknown and blocked distinctly; never say media is missing when its Library record is present.
5. **Preserve approved work.** No regenerating the opening, new storyboards, duplicate projects, character replacement, voice replacement, external editor detour, credit spending, audio-video remix, deployment, or overwriting the master without a specific owner-approved action and cost preflight.
6. **Continue only from verified footage.** Inspect the existing master (or have the owner open it on Android when that is the only supported route), identify the precise last played frame and audio, then execute at most the next authorized edit. Keep the versioned master untouched.
7. **Checkpoint.** Store the resulting version, media provenance, manifest relation, file/provider identity, what was visually/audibly proven, approvals, credit cost, and single next gate back in the **private THY Library**. Do not write narrative, personal details, raw media, private IDs, or private access URLs into public engineering repos.
